Spec 9.1.4 judges each corpus case against the vendor's outcome, not the corpus's
expectation. A case is listed here when the two differ. The library must match the

commit's subject.

Vendor: go.mongodb.org/mongo-driver v1.17.10.

What is judged:

- `valid` and degenerate_bson: the vendor decodes the bytes into a bson.D and encodes it back to the canonical bytes.
- `decodeErrors`: the vendor's Unmarshal into a bson.D returns an error (a panic is a divergence too).
- `parseErrors`: the vendor's UnmarshalExtJSON (canonical) into a bson.D, or the Marshal of its result, returns an error. A decimal128 file's strings are wrapped in a numberDecimal field first.
- Extended JSON output (canonical_extjson and the like) is not judged here: step 5 owns it.
